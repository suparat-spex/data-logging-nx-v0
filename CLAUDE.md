# NX Logger

PySide6 desktop data logger (Yokogawa GA10 style, SCADA-like connectivity like Genesis64 /
FUXA): devices (Simulation, Modbus TCP / RTU, MQTT, OPC UA; OPC DA planned) hold tags; the
app shows them in free-form views (snap grid), alarms, computes statistics and records them.
Formerly SX Logger / MQDAQ (MQTT waveform logger; last flat-file version: git tag `v6-mqdaq`).

## Layout (src/nxlogger)

| Path | Owns |
|---|---|
| `core/` | **No Qt.** `tags` (DeviceCfg, TagCfg, connector schemas `DRIVERS`, ScanBlock, tag CSV), `project` (model + file migration .sxl/.mqdaq -> .nxl), `view_model` (views: components with x / y / w / h on a snap grid; grid-layout views from 2.0 convert), `stat_buffer` (statistics windows s / min / h / samples, moving / block), `ring` (live buffers), `recording` (CSV / WPK writers, Recorder, zstd/gzip), `ml_log` (AI/ML data log), `alarm_rules` (AlarmEngine, Notifier), `channel_math` (scaling, safe formulas), `analysis` (statistics, FFT, STFT, histogram), `variables` (calculated tags), `templates` (Start Page > New project), `log_types` (logging types: interval, on change, trigger, event, batch / shift, statistics; conditions, `Gate`), `log_files` (where a profile writes: its folder, date folders, new file per session / hour / day / week / month / N MB / run, name tokens, keep days), `assets` (Project tree > Assets: Enterprise > Area / Zone / Production > Machine / Station / Unit > tags; templates + Map tags, KPI attributes, rollups, status; Collections / 2.x Assets / groups of older projects become areas and machines), `virtual_tags` (Tags > Virtual: constants, formulas, conversions, logic, selectors, text maps), `aggregation` (Tags > Aggregation: statistic, totalizer, counter, runtime, min / max hold, change; periods / resets, retain), `system_tags` (System Tags: clock, app, recording, device status), `wavepacket` (ESP32 packet format) |

## Commands

```
pip install -e ".[dev]"                 # once
python -m nxlogger                      # app        (python -m nxlogger.sim = waveform publisher)
python -m nxlogger.sim.water_plant      # water treatment plant over MQTT (--help; --export-device wtp.json)
python -m nxlogger.sim.water_plant_gui  # the same with a window (live values, copy topic / JSON path)
python -m nxlogger.sim.factory_energy_gui  # factory energy: 11 meters on Modbus TCP 127.0.0.1:5020 (--speed 60)
python -m pytest -q                     # fast tests (Modbus / OPC UA tests start local servers)
python -m pyflakes src tests            # lint
.\packaging\build.ps1                   # EXE + installer
```

Full end-to-end check (local Modbus + OPC UA servers, alarms, recording, screenshots): see the `nxlogger-dev` skill.

## Rules

- `core/` never imports Qt or `ui/`; `comms/drivers` never import Qt. Only `paths.py` knows where files are; only `icons.py` loads icons.
- Use git branches for new versions - never copy files to `_2`, `_backup`.
- Project files are JSON (`.nxl`, `"version": 2`; `.sxl` / `.mqdaq` still open). New fields need defaults + migration in `Project.from_dict` / `normalize_view` / `normalize_tile`.
- Live data is keyed `(device_id, tag_index)`; a tag's index never changes. Variables (`("var:<id>", 0)`, `core/variables.py`) are kept only for older projects: no tree node, no document, no editor - they still compute and log; new calculations are Virtual / Aggregation tags. `variables.VarBlock` is the one-sample block that System / Virtual / Aggregation tags feed with.
  In formulas a tag is `<device>_<tag>` (`channel_math.identifier`).
- New connector: schema in `core/tags.DRIVERS`, driver in `comms/drivers/` (subclass `PollDriver`: open / read / close / do_write), case in `make_driver`, a Connection page in `ui/dialogs/device_pages/<name>.py` (+ `PAGES`), test against a local server in `tests/test_drivers.py`.
- Colours only from theme tokens (`T["bad"]`, `@border@` in QSS). Must look right in dark + light (Fusion style only).
- Formulas go through `channel_math.compile_expr` / `compile_formula` (AST whitelist) - never `eval` user text.
- Threads: drivers and paho callbacks only queue; decode / scale / alarms / statistics on the GUI timer; disk + REST in workers.
- The grid-layout view version is kept on branch `nx-views-grid` (not merged).
- Tabs vs pop-ups: **docs/ui-guidelines.md**. Saved items open in editor tabs (`DaqWindow.open_editor(what, ident, **ctx)`, a `_spec_<what>`: alarm, aprofile, mllog); new items are drafts until Apply. Pop-ups only for actions: subclass `common.ActionDialog`, confirm with `common.confirm` / `ask_unsaved` - never `QMessageBox.question` / `QInputDialog` directly. Background events never open a pop-up. The project, devices, tags, assets, templates, logging profiles, virtual and aggregation tags, views and view components are the exception: settings pop-ups (`_project_popup`, `_device_popup`, `_tag_popup`, `_asset_popup`, `_template_popup`, `_log_profile_popup`, `_vt_popup`, `_agg_popup`, `_view_popup`, `_tile_popup`; `common.popup_form`, tabs style) and read-only in Properties.
- Connectivity document = connector list + device table only (no tags; right-click only on device rows); device settings are a pop-up (`DaqWindow._device_popup`), not a tab, and read-only in Properties (`PropTarget.readonly`). Right side: Properties dock + Runtime dock (`runtime_dock`). Tags document = tag management.
- Toolbars never move: changing text -> `ui_kit.fixed_width(w, *texts)`; disable buttons, don't hide them.
- Project tree: Connectivity = three flat categories (Protocols, Database, Web Services - `core/tags.CONN_CATEGORIES`, a driver's `category`; the Connectivity document lists connectors > devices, like Tags); Tags = All tags + six flat categories (All tags, Device, Virtual, Action, Aggregation, Memory, System - `tags_page.CATEGORIES`; no groups: search / sort and an Assets column); Assets · <Enterprise> = its areas, one level (`("asset", id)`), then Templates (`("templates", None)`); machines and tags only in the Assets document; Logging = the six logging types, one level (`("logtype", key)`, `log_types.TYPES`), profiles only in the Logging document (the node itself: every profile + the log folder); no Variables node; at startup the Start Page is the only tab (other documents and views open as tabs when used); the project root opens the Start Page (closable, back from the house / Project menu / Ctrl+0); Quick View (live plots) is in the Project menu and no longer opens at startup.
- Views have a fixed canvas (`width` x `height`, default 1920 x 1080, `align` left / center; View pop-up > Size): it never stretches, the scroll area shows scroll bars, components stay inside it (drag, resize, Position tab). Home / New / Open / Save on the toolbar are icons only, always (`_icon_only`).
- Monitor mode (`DaqWindow.enter_monitor` / `exit_monitor`, `ui/widgets/monitor_bar.py`): full-screen views for watching - everything but the view and the slim Monitor bar hidden, the layout restored on exit (`saveState`); F11 / Esc / Page Up / Page Down; options per PC in QSettings `monitor/...`. A logger display, not a control HMI.
- System Tags (`core/system_tags.py`): fixed, read-only, key `("sys:<id>", 0)`, computed on the 500 ms stats timer and fed like a device block (streams, alarms, statistics, formulas `System_<name>`).
- Virtual tags (`core/virtual_tags.py`, `project.virtual_tags`): derived values - inputs in, value out, no state, not written at runtime. Key `("vt:<id>", 0)`, formulas `Virtual_<name>`; scalar formulas go through `channel_math.compile_scalar` (AST interpreter, text allowed). Calculated on the GUI timer after the queue drains; numbers / booleans fed like System Tags, text shown only. Signal processing stays in Variables.
- Aggregation tags (`core/aggregation.py`, `project.aggregations`): values with state over time. Key `("agg:<id>", 0)` = value, `1` = previous period (`keep_prev`); formulas `Aggregation_<name>` / `_Previous`. Updated on the GUI timer after Virtual tags; a bad / stale source pauses them. Running values (retain) go to `paths.data_dir()/aggregation_state.json` (a worker writes, every 30 s and on exit) - never into the project file.
- Logging (`core/log_types.py`, `project.logging_profiles`): a profile has a `type` - interval (`when.every_s`, 0 = every value; "signal" of older files), change (deadband abs / %, heartbeat, min gap), trigger (start / stop conditions, debounce, pre / post-trigger, `run` column), event (alarm / condition / schedule / marker -> one row of any tags, `<profile>.csv`), batch (shift times or a start condition, `batch` column + `_summary.csv`), statistic (`interval_s`, `stats`) - and `when` (`lt.DEFAULT_WHEN`, `lt.normalize_when`). A condition = `{key, op, value}` (a Virtual logic tag for anything else). While recording `DaqWindow._gates` holds a `lt.Gate` per trigger / batch / event profile, updated on the stats timer (`_update_gates`), alarms (`_on_alarm_event`) and the Marker (`_ml_marker`); they call `Recorder.gate` / `Recorder.event` (queued, written in the recorder thread: `ChangeCsvSink`, `GateCsvSink`, `EventCsvSink`). Where: `output` (`core/log_files.py`, `lf.default_output(kind)` for new profiles - older ones keep the session folder and a file per session): `folder` ("" = the project default `logging.folder`), `folders` (session / year / year_month / ymd / date / custom pattern), `new_file`, `name` (tokens), `compress`, `keep_days`. The Recorder's `RotFile` opens a period's file on its first row (appends to a file of the same name and columns), writes `index.json` in date folders and always `project.json` in the session folder; a folder that cannot be made stops only that profile (`rec.errors`). Settings: a pop-up (`_log_profile_popup`, `LogProfileDialog` tabs General / When / Tags / Output - preview of the file now and next), read-only in Properties.
- Assets (`core/assets.py`, `project.enterprise` / `assets` / `asset_templates`): three levels - the Enterprise (the project; "" = its name, set in the Project pop-up), areas (`LEVEL2`: Area / Zone / Production, parent None), machines (`LEVEL3`: Machine / Station / Unit, parent = an area); types are labels and icons only (`am.ICONS`, "" = the type's, `am.icon_of`). Attributes reference tags of any category by key (`{"key": [tid, idx] | None, "name": short name, "kpi": bool}`) - many-to-many, assets never own tags; areas can hold tags too. Templates (`{"name", "unit", "kpi", "match"}` slots): `am.apply_template` adds slots (key None = Not mapped), Map tags... (`map_tags_dialog`, `am.map_tags` by the match pattern) fills them. KPI attributes = Start Page Key values / Monitor bar chips (`DaqWindow.kpi_values`); rollup = the sum of each machine's first KPI value (`am.rollup`); status dots alarm / ok / none (`am.status`, `DaqWindow.asset_state`, refreshed on every 4th live update; `icons.status_icon`). Tags have no groups: `TagCfg.group`, `DeviceCfg.groups`, `project.groups`, virtual / aggregation `group`, the 2.x `assets` (no `type`) and the Collections of this branch (`collections`) are read from older files and become areas and machines by `am.migrate` (load, templates, tag / device import; an empty starter collection goes, an "Equipment" one lifts its children; logging profiles' `collections` -> `assets`). Every tag picker (`common.ChannelPicker`) has By tag / By asset (`ChannelPicker.asset_source`, set by the window) and "Select <name> in all"; logging profiles can take whole assets (`assets`: ids, kept live).
- Put scratch files in the session scratchpad, not the repo.
